# GymOS × Gymawy — Feature Gap Analysis

**تاريخ الفحص: 25 أكتوبر 2026 — فرع تطوير فقط، لا دمج أو نشر أو تعديل إنتاج.**

## منهج الفحص وحدود الدليل

المصدر الرسمي العام: [SAAS Egypt](https://saasegypt.com/). رابط المستخدم [Gymawy](https://saasegypt.com/gym/index.php?cd=2026-10-24) يحيل إلى الدخول عند غياب الجلسة. أنشأ المستخدم الحساب التجريبي بنفسه، ثم فُتحت لوحة المدير بإذنه. تمت زيارة القوائم المتاحة عبر واجهة المتصفح، لا باستدعاء APIs خفية أو تخمين مسارات. لم تُرسل رسائل، ولم يُنفذ دفع أو تحديث قاعدة أو حذف أو حفظ نموذج. لم تُجمع أسماء أو أرقام أو سجلات أشخاص في هذا التقرير أو في شيفرة GymOS. ظهور سجلات في حساب تجريبي لا يثبت أنها تخص أشخاصًا وهميين؛ لذلك لم تُستخدم كبيانات اختبار.

دليل الواجهة يعني وجود الشاشة/النموذج فقط، **وليس إثبات صحة الحفظ أو الحساب أو التسليم أو العزل الداخلي**. المميزات المعلنة في الصفحة العامة تُفصل عن المميزات المشاهدة. إدارة المستخدمين والإعدادات أظهرت «اشتراك مطلوب»، وهوية النظام محمية؛ لم تُتجاوز هذه القيود. لم تُفتح وظيفة تحديث قاعدة البيانات لأنها قد تغير النظام. الفحص لا يثبت اكتمال كل شاشة مخفية أو كل خطة تجارية.

قورنت الشيفرة الفعلية في `main` عند `2fbe2f7`، مع فحص مستقل للفرع غير المدموج `codex/commercial-core-hardening-20261024` عند `9c18102` / PR32. هذا الفرع الجديد يبدأ من main ولا يستورد تغيير PR32 الخاص بمنع PIN الافتراضي؛ دخول الأعضاء لم يتغير.

الحالات أدناه تخص GymOS قبل هذه الدفعة: **موجودة، موجودة جزئيًا، ناقصة، تحتاج تحققًا**. الأولوية P0 قبل ادعاء الجاهزية التجارية، P1 قيمة تشغيلية مرتفعة، P2 توسع لاحق. لا تعني المقارنة تفوقًا مقاسًا أو نسخًا للتصميم.

## التنفيذ الأصلي في هذه الدفعة

1. **GYM OS Connect:** شاشة مجمعة للفرع، أعداد أولوية، بحث عن العضو/الهاتف/التذكرة/الجهاز، فتح ملف العضو مباشرة، عرض كل الأقسام أو التركيز على قسم. لا شاشات مالية أو صحية للاستقبال. عرض القوائم محدود مع بحث؛ ليس pagination خادميًا أو تحسينًا شاملًا لكل الشاشات.
2. **متابعة تجديد deterministic:** يعتمد آخر نهاية غير ملغاة، يمنع التذكير المبكر عند وجود تجديد محجوز، ويتجاهل الأعضاء المؤرشفين والتجريبيين والتجميد الساري. يشرح تاريخ الانتهاء والسبب. لا يجدد أو يقبض تلقائيًا.
3. **SMS:** موافقة مستقلة قابلة للسحب، مسودة عربية/إنجليزية، اعتماد وإلغاء، منع تكرار نفس العضو/الانتهاء، سجل حالة. موصل Twilio خادمي ثابت HTTPS ومربوط بمساحة النادي والفرع. حد افتراضي 50 طلب إرسال/فرع/يوم؛ ليس تسعيرًا نقديًا أو حد فواتير المزود. يُحفظ dispatching قبل الطلب؛ النتيجة المجهولة لا تُعاد تلقائيًا. submitted تعني قبول طلب المزود وليست تسليمًا. لا إرسال فعلي في هذه المراجعة.
4. **بوابة بصمة/حضور:** جهاز وربط معرفه المحلي بعضو الفرع؛ تفعيل/تعطيل؛ endpoint محمي HMAC-SHA256 بزمن خمس دقائق وتكرار آمن للأحداث، وربط tenant/branch من إعداد الخادم فقط. يعيد استخدام قواعد العضوية والشيفت والحضور الموجودة. لا تُخزن قوالب أو صور بصمات. هذه بوابة normalized events وليست تنفيذ ZKTeco/Anviz SDK أو فتح باب فعلي.
5. **تذاكر النادي:** موضوع/أولوية/محادثة متابعة/إغلاق، مع عزل النادي والفرع وصلاحيات المالك/المدير. هي سجل داخلي الآن، لا ادعاء وصولها لفريق دعم المنصة أو وجود SLA أو تصعيد وبريد ومرفقات.
6. **استعادة آمنة:** لا يعيد ملف قديم موافقات SMS مسحوبة، أو رسائل قابلة للإرسال من الماضي، أو جهازًا معطلًا. تُحفظ الحالات الحالية للفروع والأعضاء الباقين. JSON اختياري متوافق مع البيانات القديمة؛ النسخة الجديدة مطلوبة لاستعادة ملفات تحتوي الحقل الجديد.

## خطة التنفيذ التالية حسب القيمة التجارية

P0: قبول SMS مع مزود معتمد وقواعد المرسل/التكلفة/الإلغاء؛ استلام delivery callbacks موقعة ومصالحة النتائج المجهولة؛ اختيار جهاز وSDK ووسيط محلي واختبار دخول/خروج/انقطاع/إعادة إرسال؛ دفتر مصروفات وربطه بالخزنة والتقارير؛ استعادة وتزامن مالي على قاعدة تجريبية حقيقية.

P1: فواتير الموردين، شيفتات الخزنة، زيارة سريعة، حضور المدربين وHR، استحقاق الفروع، صلاحيات مدير تفصيلية، ربط التذاكر بفريق دعم المنصة بتفويض واضح ومقيد بتذكرة وسجل وصول. دعم الموظف لا يساوي إعطاء فريق المنصة حق قراءة كل بيانات النادي.

P2: بطولات وإنجازات، عمولات مبيعات الموظفين، بوابة المدرب، منشورات ومحادثات أعضاء، مقارنة سهولة الاستخدام بمستخدمين ومهام مقاسة.

## الموارد والقبول

SMS يحتاج حساب مزود ومرسل معتمد وميزانية واختبار تسليم وأرقام اختبار يوافق أصحابها. راجع [توثيق Messages الرسمي](https://www.twilio.com/docs/messaging/api/message-resource). لا يوجد التزام بأن Twilio أفضل مزود لمصر؛ اختيار المزود المحلي يحتاج عرضًا وموافقة مشغل الاتصالات.

البصمة تحتاج طرازًا/firmware/SDK وجهازًا فعليًا ووسيطًا محليًا وسرًا مستقلًا لكل جهاز؛ الربط لا يثبت liveness أو صحة التعرف ولا يفتح بوابة مادية. تحميل بصمات/مزامنة مستخدمي الأجهزة خارج النطاق الحالي.

للتفعيل المستقبلي، إعدادا `GYMOS_SMS_ENABLED` و`GYMOS_DEVICE_BRIDGE_ENABLED` يظلان 0 افتراضيًا. الأسرار خادمية وليست في ملفات العميل أو النسخ أو التقارير. أمثلة البنية وخطوات القبول في `GYMOS_CONNECT_SETUP_AR_EN.md`. الاختبارات تستخدم بيانات مصطنعة وtransport/storage doubles، لا بيانات إنتاج.

الفرع منفصل وعمليات Vercel التلقائية له معطلة في `vercel.json` وفق [التوثيق الرسمي](https://vercel.com/docs/project-configuration/git-configuration). لا دمج أو نشر بدون موافقة المستخدم. لا نسخ للشيفرة أو الصور أو التصميم من جيماوي، ولا ادعاء اكتمال جميع الفجوات أو التفوق على المنافس قبل قبولها وقياسها.

## نتائج التحقق النهائية لهذه الدفعة

129 اختبار وحدات ناجح، 7 اختبارات قاعدة اختيارية متخطاة. 6 اختبارات API جديدة ناجحة للعرض والصلاحيات وtenant binding وادعاء SMS قبل الاتصال ومنع التكرار والنتيجة المجهولة وحد اليوم وتوقيع الجهاز وإعادة الحدث. اختبارات الدور الحالية 5، عرض العضو 2، جلسات العضو 7: إجمالي 149 ناجحًا. TypeScript وESLint وgit diff --check نجحت. البناء الإنتاجي المحلي نجح بعد السماح بتشغيل العمليات المساعدة وتنظيف أنواع صفحة اختبار محلية محذوفة؛ لم يُتجاوز فحص نوع أو اعتماد أو أمان. السجلات المرفقة في docs/verification/2026-10-25-gymawy/.

الاختبارات تستورد route handlers الفعلية لكن تعتمد بدائل تخزين وهوية وHTTP مصطنعة؛ لم تُجر اختبارات PostgreSQL حقيقية أو حمل أو استعادة إنتاج في هذه الدفعة. فحص متصفح محلي ببيانات مصطنعة: اعتماد مسودة وإغلاق تذكرة، عربي عند390، إنجليزي عند320 وكمبيوتر1280؛ scrollWidth يطابق clientWidth. صفحة fixture المؤقتة أزيلت قبل البناء النهائي؛ كانت تولد معرفات/توقيتًا عشوائيًا أثناء SSR مما سبب تحذير hydration في fixture فقط، ثم أعاد React عرضها على العميل. المكون الفعلي يفتح بعد تحميل packet في العميل. لم تختبر كل شاشات المنتج أو الأجهزة الفعلية.

بعد الدفعة: المتابعة موجودة ومُحسنة؛ SMS موجود جزئيًا (موصل وتجهيز واعتماد وإرسال يدوي، التسليم غير مختبر)؛ بصمة الأجهزة موجودة جزئيًا (عقد أحداث آمن، SDK والجهاز غير مختبرين)؛ تذاكر داخلية موجودة ومختبرة محليًا، وhelpdesk مركزي لا يزال ناقصًا. المصروفات وHR وخزنة الشيفتات وفواتير الموردين والبطولات وبقية الفجوات لم يُدع اكتمالها.
