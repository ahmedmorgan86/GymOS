# Public site, trial and search readiness — 26 October 2026

## Commercial policy
The public Try button leads to the existing real 30-day trial, not a separate mock application. The owner signs up, creates an independent club in My clubs and starts the trial. Team invitations are optional for existing staff and are never a requirement for a new owner. Existing server-side one-owner trial claims, exact expiry, license checks, RLS and branch permissions remain in force. No client timer can extend the server license. No fixed prices or package catalogue are exposed to club owners: paid activation, renewal, maintenance and support are individually quoted. Existing sold limits and chosen member PINs are preserved.

## Public experience
Anonymous root visitors see the bilingual public landing; authenticated users retain their workspace. Original interactive dashboard illustration explicitly labels all numbers as fictional. Three download destinations distinguish Windows desktop, installable management web app and member Android/iPhone experience. QR codes point to management setup and member sign-in. Reduced-motion users receive no decorative animations. No third-party animation scripts, customer data or autoplay audio are used on the public site.

## Owner verification / submission still required
1. Google Search Console: add this exact HTTPS property and copy the provided verification token to GOOGLE_SITE_VERIFICATION in the production environment. Redeploy, verify and submit sitemap.xml.
2. Bing Webmaster Tools: add this property (or import a verified Google property), put its token in BING_SITE_VERIFICATION, redeploy, verify and submit the same sitemap. Bing also serves discovery partners; it does not guarantee every search provider will index a page.
3. Yandex Webmaster if desired: use YANDEX_SITE_VERIFICATION, verify and submit the sitemap.
4. After a domain change update NEXT_PUBLIC_SITE_URL, all QR destinations, mobile install URLs and each verified property. Check canonical/redirect/HTTPS before submitting.
5. Inspect the public URL in each console. Do not submit any private club/member route. Monitor crawl reports; indexing and ranking are controlled by each engine.

No webmaster account was created, no ownership verification was claimed, and no ranking guarantee is made. Physical iPhone installation, camera/scanner acceptance and real SMS/WhatsApp provider delivery require their actual devices/accounts.

## Owner-only club design studio
Settings contains a club-scoped studio for eight colors, card/button corners, Cairo size and weight, comfortable/compact density, motion preference, club background and member pass cover. Local preview, explicit save, discard and base-theme reset are supported. JPEG/PNG/WebP uploads are resized/re-encoded as bounded JPEG; remote image URLs, arbitrary CSS, script and unknown schema fields are rejected. Contrast checks prevent unreadable text combinations. These controls customize shared visual tokens, not unrestricted code, route/workflow rearrangement or the public marketing site. Unauthenticated sign-in cannot infer an unknown club's identity.

Only the club owner can send design.save; full managers and reception are rejected server-side. A manager restoring a backup retains the current owner-approved design. Tenant workspace storage, revision checks, tenant request checks and existing RLS provide isolation. Member views receive only their own club's design. Existing 14 themes and uploaded club logos remain available. Windows uses the same hosted UI.
