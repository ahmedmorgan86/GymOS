# ربط واتساب داخل GYM OS خطوة بخطوة

الإصدار: 23 أكتوبر 2026. الربط الحالي يدوي مع WhatsApp Business Platform / Cloud API. لا يستخدم QR الخاص بواتساب ويب، ولا يكفي تثبيت تطبيق WhatsApp Business على الهاتف.

## 1. جهّز حساب ورقم النادي

افتح https://business.facebook.com/ بحساب يملك صلاحية إدارة نشاط النادي. جهّز Business Portfolio وحساب WhatsApp Business Account (WABA) ورقم إرسال يستطيع استقبال رمز تحقق SMS أو مكالمة. افتح https://developers.facebook.com/apps/ وأنشئ/اختر تطبيقًا مرتبطًا بنشاط النادي وأضف حالة استخدام WhatsApp. أسماء قوائم Meta قد تتغير؛ ابحث عن WhatsApp وAPI Setup أو Getting Started أو Production Setup.

ابدأ برقم اختبار Meta ومستلم اختباري موثق إن لم تسجل رقم الإنتاج بعد. عند استخدام رقم موجود على واتساب الهاتف، اتبع مسار Meta المعروض لنقله أو دعمه بالتعايش إن كان متاحًا لحسابك؛ لا تحذف حساب الرقم عشوائيًا. قد تحتاج Meta إثبات النشاط وإعداد الدفع وحدود الإرسال قبل التشغيل التجاري. رسوم وقواعد المزود تتبع حسابك؛ GYM OS لا يمنح إرسالًا مجانيًا غير محدود.

## 2. احصل على البيانات الثلاثة الصحيحة

من WhatsApp > API Setup / Getting Started اجمع:

| الحقل داخل GYM OS | القيمة المطلوبة |
|---|---|
| Phone number ID | معرّف رقم الإرسال من Meta، وليس رقم الهاتف نفسه، وليس App ID أو WABA ID |
| Graph API version | إصدار مدعوم ظاهر في مثال طلب الإرسال داخل حساب Meta، بصيغة `v` ثم رقم الإصدار ثم `.0`؛ لا تكتب القيمة الإرشادية `vXX.0` |
| رمز الوصول | Access Token مخول للإرسال من نفس رقم النادي؛ لا ترسله في المحادثة أو تحفظه في ملف عام |

وثائق Meta الرسمية تعرض مكان Phone Number ID ورمز الاختبار في لوحة WhatsApp وتوصي باستخدام رمز مستخدم نظام للتشغيل المستمر: https://whatsapp.github.io/WhatsApp-Nodejs-SDK/

## 3. استخدم رمز تشغيل مناسبًا

رمز الاختبار المؤقت يصلح للبدء، وقد تنتهي صلاحيته. للإنتاج افتح Business Settings > Users > System Users، واختر/أنشئ مستخدم نظام، وأسند له التطبيق وحساب واتساب الصحيح بالصلاحيات اللازمة. من Generate Token اختر التطبيق والصلاحيات:

- `whatsapp_business_messaging` للإرسال.
- `whatsapp_business_management` لإدارة/قراءة أصول واتساب والقوالب عند الحاجة.
- `business_management` فقط إذا كانت إجراءات إدارة نشاطك تتطلبه، وليس شرطًا عامًا لكل إرسال.

اختر مدة متاحة تناسب التشغيل وراقب إبطال/انتهاء الرمز؛ لا تفترض أن وصف «دائم» يمنع الإبطال لاحقًا. انسخه مباشرة إلى حقل التطبيق. الحساب والرقم والرمز يجب أن يخصوا نفس النادي. وثائق Meta على Postman: https://www.postman.com/meta/whatsapp-business-platform/documentation/wlk6lh4/whatsapp-cloud-api

## 4. أنشئ قوالب الرسائل داخل Meta أولًا

من WhatsApp Manager > Message templates أنشئ قالبًا لكل غرض ولغة، وانتظر الموافقة. الاسم يكون كما اعتمدته Meta، مثل `gym_welcome`. اختر التصنيف المناسب للمحتوى؛ لا تستخدم تصنيف خدمة لإخفاء رسالة تسويقية.

مثال ترحيب عربي لعرضه على Meta:

`أهلًا {{1}}، نرحب بك في {{2}}. يسعدنا انضمامك إلى النادي.`

بعد اعتماد القالب، المتغير الأول هو اسم العضو والثاني اسم النادي. للإنجليزية أنشئ نسخة باللغة المعتمدة، مثل `en_US`، واختر نفس كود اللغة في التطبيق. لا تكتب `en` إذا كان القالب معتمدًا على `en_US`.

مثال قرب الانتهاء:

`مرحبًا {{1}}، ينتهي اشتراكك في {{2}} يوم {{3}}. تواصل مع إدارة النادي لمراجعة التجديد.`

لإرسال السياسات: أنشئ قالبًا يحتوي على Header من نوع Document، واعتمده. حقل رابط PDF داخل GYM OS مخصص لقالب بهذه البنية؛ وضع الرابط مع قالب نصي بلا Header مناسب يفشل. يجب أن يكون ملف السياسة HTTPS قابلًا لوصول Meta، دون كشف بيانات أعضاء.

## 5. احفظ الربط داخل GYM OS

1. سجّل كمالك النادي أو مدير مخول للفرع.
2. اختر النادي الصحيح ثم الفرع الصحيح من أعلى التطبيق.
3. من القائمة افتح **واتساب النادي**.
4. في **ربط رقم الفرع** أدخل Phone number ID وإصدار Graph API ورمز الوصول.
5. اضغط **حفظ الربط**. الرمز يخزن مشفرًا ولا يعاد عرضه.

ظهور الربط محفوظًا يعني حفظ الإعدادات؛ لا يثبت وحده أن Meta قبلت الرمز أو أن رسالة وصلت. التحقق الكامل يكون بإرسال قالب اختباري فعلي في الخطوة 8.

## 6. اضبط أرقام الأعضاء والموافقة

رقم العضو يجب أن يكون دوليًا، مثل `+201012345678` بدلًا من `01012345678`. راجع الدولة والرقم الفعلي. في **موافقات الأعضاء** فعّل واتساب فقط للعضو الذي وافق صراحةً. موافقة التواصل العامة لا تقوم مقام موافقة واتساب. الحسابات المؤرشفة والبيانات التجريبية لا تستقبل الرسائل المجدولة.

كل نادٍ يرى أعضاءه وفروعه المخولة فقط. لا تستخدم إعدادات نادي لإرسال رسائل لأعضاء نادٍ آخر. لإيقاف الرسائل لعضو، ألغِ موافقته قبل الجولة التالية؛ الرسالة التي قبلها المزود بالفعل لا يمكن سحبها من داخل هذه الشاشة.

## 7. أنشئ القواعد والمتغيرات

اكتب اسم القاعدة، اختر الحدث، ثم وقت الإرسال **بتوقيت النادي** واسم قالب Meta ولغته. اكتب متغيرات القالب بالترتيب، **كل متغير في سطر مستقل**. لقالب الترحيب أعلاه اكتب:

```
{name}
{gym}
```

ولقالب الانتهاء ذي المتغيرات الثلاثة:

```
{name}
{gym}
{expires}
```

هذه هي البدائل المتاحة حاليًا. العدد والترتيب يجب أن يطابقا قالب Meta المعتمد. لا تضع نص القالب كاملًا في حقل اسم القالب. اضبط القاعدة على مفعّلة ثم احفظها.

| الحدث | إعداد وتشغيل القاعدة الحالية |
|---|---|
| الترحيب / السياسات | العضو الجديد ضمن نافذة 7 أيام، وبداية انضمامه ليست أقدم من يوم إنشاء القاعدة؛ لا ترحب تلقائيًا بكل الأعضاء القدامى |
| عيد الميلاد | يحتاج تاريخ ميلاد محفوظًا بموافقة العضو ويطابق يوم المناسبة |
| مناسبة بتاريخ محدد | حدد تاريخ المناسبة؛ ترسل في يومها بعد الوقت المختار |
| غياب | حدد عدد أيام الغياب؛ يعتمد على آخر يوم حضور أو تاريخ الانضمام مع عضوية سارية |
| قبل الانتهاء | حدد عدد الأيام؛ تنطبق عندما يساوي تاريخ الانتهاء اليوم مضافًا إليه هذا العدد |
| انتهاء العضوية | تنطبق بعد الانتهاء ضمن نافذة 7 أيام |

المعالجة كل خمس دقائق، وقد تتأخر عن الدقيقة المختارة. تستعمل القواعد تاريخًا/حدثًا لمنع التكرار. لا توجد محاولة تلقائية جديدة لكل رسالة غير مؤكدة، ولا تعني إعادة الضغط إعادة إرسال مضمونًا.

## 8. اختبار حقيقي مضبوط

استخدم عضو اختبار غير موسوم كبيانات تجريبية، برقم تملكه أو وافق صاحبه على الاختبار. لا تستخدم أعضاء حقيقيين لاختبار عشوائي. وافق على واتساب، وأنشئ قاعدة مناسبة مستحقة اليوم، بقالب معتمد وعدد متغيرات صحيح. تأكد أن وقتها قد حان وأن تاريخ انضمام العضو مناسب للترحيب. في رقم Meta الاختباري يجب أن يكون المستلم ضمن قائمة الاختبار الموثقة.

اضغط **تشغيل المستحق الآن** بعد مراجعة المستلمين؛ هذا قد يرسل الرسائل المستحقة فعلًا، وليس زر معاينة. افحص **سجل الإرسال** ثم واتساب المستلم نفسه. لا يتم إرسال رسائل حقيقية من هذه الحزمة بدون ربط حسابك وموافقة المستلم.

## 9. فهم الأخطاء

- غير مرتبط: راجع النادي/الفرع وحفظ البيانات.
- رفض المزود: راجع صلاحية الرمز وملكية الرقم والتصاريح وإصدار API واعتماد القالب واللغة والمتغيرات وقيود الحساب. كود `provider_...` يظهر للتشخيص دون كشف الرمز.
- لا رسائل مستحقة: راجع موافقة العضو ورقمه وتاريخ الحدث والوقت والتوقيت وحالة العضوية والترخيص. البيانات التجريبية مستبعدة.
- `sent` أو قبول المزود: الطلب قُبل، ولا يثبت وصوله أو قراءته. أكّد من هاتف المستلم.
- `unknown`: النتيجة غير مؤكدة؛ قد تكون الرسالة وصلت. راجع حساب المزود والمستلم قبل أي إجراء يدوي؛ لا تعِد الإرسال عشوائيًا.

## 10. حدود النسخة الحالية

إعدادات كل نادٍ وفرع معزولة وصلاحيات تعديلها للمالك والمدير المخول. لا يوجد ربط OAuth تلقائي موحد لكل أندية العملاء، ولا صندوق محادثات واردة أو Webhook لتأكيد التسليم/القراءة أو معالجة رد STOP تلقائيًا. عند طلب عضو إيقاف الرسائل، أوقف موافقته يدويًا وراجع الردود عبر أداة إدارة واتساب التي تستخدمها. إضافة قناة واردة كاملة تحتاج تنفيذًا واختبارات منفصلة.

## English quick reference

Use Meta WhatsApp Business Platform, not WhatsApp Web QR login. Provision the club's business number/app; obtain its Phone Number ID, a supported Graph API version and a properly scoped system-user access token. Approve templates/languages in Meta. In GYM OS select the correct club/branch, open Club WhatsApp, save the three connection fields, enable explicit member opt-in, and create due rules with parameters `{name}`, `{gym}`, `{expires}` in exact template order, one per line. Test only with a consenting recipient. Run due can send real messages. Provider acceptance is not delivery confirmation. Unknown attempts are not automatically retried. Current setup has no inbound inbox/STOP or delivery-receipt webhook.
